# Глоссарий {#glossary}

## Обзор статьи {#article-overview}

- **Имена и значения в тексте**: Заключать в обратные апострофы (строчный код, inline code) технические названия: имена
полей метаданных, значения справочников и статусов, переменные, параметры, команды, имена файлов, каталогов и путей.
Например: статус `archived`, поле `replaced_by`, файл `settings.json`. Причина: Апострофы отделяют точное техническое
имя от слов текста, и читатель сразу видит, что его нужно вводить или искать дословно. Подчёркивание внутри имени
(`replaced_by`) не превращается в курсив, а лексический поиск находит имя как отдельный термин.
- **Только для технических названий**: Для обычных слов и терминов апострофы не использовать, акцент передавать
полужирным начертанием. Причина: Если строчным кодом помечены обычные слова, он перестаёт отличать технические имена.
- **Имя целиком и в одной строке**: Имя или команду заключать в апострофы целиком, без пробелов внутри апострофов, и не
переносить на другую строку. Многострочные команды и код оформлять блоком кода. Причина: Перенос внутри апострофов
превращается в пробел и искажает имя, а блок кода сохраняет переносы и отступы.

Пример блока кода:

```python
import os
import sys
```
