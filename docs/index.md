# О программном продукте

Пример организации требований для программного продукта с использованием подхода Docs as Code: спецификации 
функциональностей продукта хранятся в репозитории как Markdown-файлы, а перечень функциональностей (продукта, модулей) и 
сайт собираются автоматически.

<div class="grid cards" markdown>

- :lucide-book-open: [**Глоссарий**](glossary.md#article-overview)

    Перечень терминов, описывающих предметную область программного продукта. Он необходим для того, чтобы вся команда 
    одинаково понимала используемые понятия.

- :lucide-map: [**Карта функциональностей**](feature-map.md#article-overview)

    Интерактивное дерево требований продукта. Оно собирается автоматически и содержит полный список спецификаций с их 
    текущими статусами и прямыми ссылками.

- :lucide-files: [**Спецификации**](specifications/index.md)

    База действующих требований к продукту, организованная по модулям и подмодулям для удобной навигации по архитектуре 
    системы.

- :lucide-archive: [**Архив спецификаций**](archive/index.md)

    Историческая база отклоненных и устаревших требований. Повторяет актуальную структуру модулей и подмодулей, что 
    позволяет легко найти контекст старых требований.

</div>
