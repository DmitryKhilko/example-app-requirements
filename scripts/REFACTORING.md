## 3. План

Принцип: шаги идут по возрастанию риска, каждый самостоятельный, один коммит на шаг. Проверка каждого шага:
эталон `generate_docs.py --check` + побайтное совпадение генерируемых файлов + (с шага 1) ruff, mypy, pytest;
для шагов с JS и CSS ещё Playwright и сравнение стилей. Откат: `git revert` коммита шага. Размер: больше примерно
10 файлов не затрагивается, иначе шаг разбит.

Ответьте одной строкой («везде по умолчанию» подходит). Моя рекомендация указана первой.

   остаются привязанными к `archive` (описать в README как ограничение). Альтернатива: считать параметр неизменяемым.
5. **Размер `config.py`.** 197 строк. **По умолчанию:** не дробить, добавить раздел «Контракт разметки»; дробить, когда
   перейдёт за 400 строк или по вашему желанию.
6. **Файлы блокировок.** Мне недоступны PyPI и npm, поэтому `uv.lock` и `package-lock.json` создаёте вы (`uv lock`,
   `npm install`) и коммитите после шага 1. ESLint и Stylelint я тоже не смогу запустить: JS и CSS проверяю
   Playwright-тестами и вручную. **По умолчанию: согласны.**
7. **`zensical.toml`.** Закомментированные блоки (`exclude_docs`, лишние `features`) и дубль подписей статусов

   подписей отслеживает тест (шаг 1).
8. **Шаг 8 (границы модулей).** Он самый крупный по структуре. **По умолчанию:** делаем в два подшага (8а: `validate/`,

## 9. Аудит (полный текст)

### Что уже сделано хорошо (не трогать)

* Пакет `docgen/` с чёткими этапами «чтение → проверка → генерация → применение» и описанием в `__init__.py`; нет
  циклических импортов, зависимости идут сверху вниз (проверено чтением и поиском импортов).

  инициализации, проверки на `null`, нет `console.*`; подробные пояснения в шапке файлов.
